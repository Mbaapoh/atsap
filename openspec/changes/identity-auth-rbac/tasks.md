## 3. Credentials and tokens

- [x] 3.1 Implement the Argon2id hasher at the design's fixed parameters (19 MiB, 2 iterations, parallelism 1), and verify a unit test asserts those exact parameters are used and that hash-then-verify round-trips while the stored value contains no recoverable password (`application.PasswordHasher`, PHC-format output so parameters travel with each hash. `Verify` reads the parameters **from the stored hash**, not from today's constants — that is what makes raising the cost factor later a non-breaking change instead of a mass lockout, pinned by its own test. Constant-time digest comparison. Fresh per-call salt, so two accounts sharing a password are not identifiable from stored values. Malformed hashes return a distinct `ErrInvalidHashFormat` — an operational fault, not a routine wrong-password answer. `go mod tidy` moved `golang.org/x/crypto` indirect→direct; nothing new entered the build, and TOOLSET.md line 120 already mandates this exact package)
- [x] 3.2 Implement API key generation (cryptographically random, high entropy), SHA-256 digest storage, and one-time reveal, and verify a unit test asserts the raw key is returned exactly once and only a digest is persisted (`GenerateAPIKey` returns `(raw, digest)` — the raw value is never persisted and is unrecoverable from the digest, so losing it means reissuing, which is the intended behaviour. 256 bits from `crypto/rand`; an `atsa_` prefix so a key leaked into a log or paste is recognisable as a credential to revoke rather than an anonymous blob. Constant-time verification. SHA-256 rather than Argon2id is justified in-code by the entropy argument, with the uniqueness test that backs that claim)
- [x] 3.3 Implement token issuing on stdlib `crypto/ed25519` (header + claims + signature, no JWT library), and verify a unit test decodes the produced token and reads back tenant, principal, roles, and expiry (`application.TokenIssuer` on stdlib `crypto/ed25519` + `encoding/json` + `encoding/base64` — no JWT dependency, so TOOLSET §6 is never engaged. `WithClock` injects the time source so expiry is driven deterministically rather than by sleeping. A malformed signing key fails at construction, not at first use)
- [x] 3.4 Implement token validation with the accepted algorithm pinned in configuration and `exp`/`nbf` enforcement, and verify unit tests reject `alg: none`, a different declared algorithm, an expired token, and a token whose signature was altered (the algorithm is a **constant compared against the header**, never read from it to select a verifier — the confusion class is designed out rather than coded around, and the check runs *before* any signature work. Tests cover `alg: none`, `HS256`/`RS256`/`ES256` downgrades, and case/whitespace variants (`eddsa`, `EdDSA `) a naive comparison would admit; plus tampered claims re-encoded without re-signing, a validly-signed token from a *different* issuer key, expiry pinned exactly at the boundary so a later `>=`->`>` slip fails, and `nbf`. OWASP A02/A07; DoD item 12)
