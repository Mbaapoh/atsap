# Architectural Decisions & Technical Resolutions (T-1 to T-12)

This document provides the definitive technical resolutions for the 12 open technical questions raised in `docs/PRD.md` §16.2, and records the Architectural Decision Records (ADRs) derived from `docs/DECISIONS.md`.

---

## 1. Definitive Resolutions for PRD Technical Questions (T-1 to T-12)

| Question ID & Topic | Product Constraint (PRD §16.2) | Authoritative Architectural Resolution | Trace |
|---|---|---|---|
| **T-1: Entitlement Confirmation & Installation Identity** | Must never sit in the path of a call. Must tolerate unreachable service for 7-day grace without functional change. | **Ed25519 Cryptographic Token + Weighted Hardware Fingerprint.** License token is installed locally; daily verification worker checks cloud entitlement endpoint asynchronously. Calls evaluate local in-memory entitlement cache only (0 ms latency). Offline grace lasts 7 days; warnings start on day 2; degrades on day 8 to base tier without full shutdown. | [04](04-bounded-contexts.md) §4, [05](05-security.md) §1; DECISIONS D-12, D-13, D-14 |
| **T-2: Atomic Concurrent Capacity Counting** | Must be exact under simultaneous call setup. Must never miscount or reject calls below licensed limit. | **Atomic Lock-Free Memory Counters + Shared Ingress Guard.** Active channels are tracked via atomic Go counters (`atomic.Int64`) incremented upon Stasis ingress and decremented upon bridge exit. Race-tested at 10× normal setup rate (300 CPS) with zero drift. | [01](01-architecture.md) §2, [04](04-bounded-contexts.md) §4; BR-05, AC-06.10 |
| **T-3: Overflow / Burst Allowance Mechanics** | Must absorb ordinary busy-hour peaks without allowing sustained unauthorized over-use. | **10% Channel Burst Allowance with 15-Minute Sliding Window.** A deployment with 500 licensed channels permits up to 550 channels for up to 15 continuous minutes. If utilization remains above 100% after 15 minutes, new call setups are rejected with SIP `503 Service Unavailable` (`Retry-After: 30`) until utilization drops below 95%. | [04](04-bounded-contexts.md) §4, [09](09-failure-model.md) §2; BR-05, D-11 |
| **T-4: Audio Delivery to AI Without Quality Degradation** | Zero measurable quality impact on calls. Provider failure must be completely invisible to call audio. | **Asterisk Out-of-Band ARI Snoop Channel + Non-Blocking Frame Buffer.** AI audio consumes a cloned stream (`ARI /channels/{id}/snoop`). Go AI adapter uses bounded tail-drop buffers (250 ms max). Slow or dead AI providers drop frames silently without backpressuring the Asterisk bridge. Call audio remains 100% active. | [02](02-system-context.md) §3, [04](04-bounded-contexts.md) §6; DECISIONS D-05, D-23, INV-04 |
| **T-5: Per-Participant Identity Across Transfers** | Billable duration must reflect continuous participation, not internal reconnection. | **AtsaPBX Correlation Token + ACL `ChannelHistory` Mapping.** `Call` aggregate contains stable `CallParticipant` entities. During blind or attended transfers, Asterisk channel swaps are logged as sequential `ChannelHistory` rows tied to the same `participant_id`. Billing and CDR timers remain continuous and unbroken. | [01](01-architecture.md) §2, [03](03-domain-model.md) §3; DECISIONS D-17, D-18, D-32 |
| **T-6: Route Health Measurement Window** | Must detect genuine route failure quickly without reacting to isolated transient errors. | **Rolling 60-Second Window + Consecutive Failure Threshold.** Route health combines background SIP `OPTIONS` pings (every 10s) with call setup failure tracking. A route is marked `DEGRADED` if 3 consecutive pings fail OR call setup failure rate exceeds 20% over a rolling 60s window (min 5 calls). Automatic failover occurs in <5s (AC-02.2). Auto-recovery requires 5 continuous minutes of healthy pings. | [02](02-system-context.md) §4, [04](04-bounded-contexts.md) §2, [09](09-failure-model.md) §1; BR-08, AC-02.2 |
| **T-7: Retained & Replayable Integration Data** | In-order delivery per destination; retention window honored; console and API replay available. | **Transactional Outbox + NATS JetStream + PostgreSQL DLQ.** Events are written in the same DB transaction as domain state, published to NATS, and consumed by `webhook-delivery`. Failed deliveries retry across 24h (1m, 5m, 15m, 1h, 6h, 24h). Dead-lettered events remain queryable and replayable via ConnectRPC API. | [01](01-architecture.md) §3, [04](04-bounded-contexts.md) §8; INV-06, AC-05.3 |
| **T-8: Enforceable & Proven Data Residency** | Must be demonstrable by automated test, not merely by inspecting configuration. | **Tenant `residency_zone` Tag + Dedicated Storage Prefixes & KMS Keys.** Every tenant has a cryptographic residency attribute (`residency_zone="EU"`). Encrypted database partitions, S3 bucket prefixes, and Vault keys are pinned to region-specific endpoints. Automated test suite verifies cross-region write attempts fail closed. | [03](03-domain-model.md) §5, [05](05-security.md) §1; BR-15, FBR-R3-07 |
| **T-9: Permanent Multi-Copy Deletion** | Must complete within SLA window across primary storage, caches, and backups, with auditable proof. | **Crypto-Shredding of Tenant Root Key + Multi-Store Hard Purge.** Tenant Master Key is destroyed in Vault, instantly rendering all historical backups, snapshots, and cold storage archives cryptographically unrecoverable. Primary tables and S3 buckets are hard-deleted. An immutable SHA-256 deletion manifest certificate is generated for auditors. | [05](05-security.md) §2; BR-11, AC-07.3 |
| **T-10: Tenant Recording Encryption & Access** | No credential or key readable by another tenant or by platform staff in plain text. | **AES-256-GCM Envelope Encryption via Vault Transit Engine.** Each recording is encrypted with an ephemeral random DEK wrapped by the tenant's KMS key. Playback requires authenticated JWT with `recording:read` role, active consent verification, and generates an append-only audit log entry. Presigned URLs expire in 60s. | [03](03-domain-model.md) §5, [05](05-security.md) §3; BR-04, BR-15, AC-07.4 |
| **T-11: Per-Participant Voice Quality Measurement** | Every call measured (not sampled); sufficient detail to resolve disputes within 10 minutes. | **Real-Time RTCP-XR Ingestion + ITU-T G.107 E-Model MOS Scoring.** Ingests jitter, packet loss, and RTT from Asterisk every 5s per participant. Computes MOS score (1.00–4.50) and records timeline in `usage_seconds`. Support engineers query exact participant audio metrics in under 2 seconds. | [03](03-domain-model.md) §1, [07](07-observability.md) §1; BR-07, AC-07.8 |
| **T-12: Zero-Downtime Upgrade & Rollback** | Rollback within 30 minutes; zero configuration or call loss; tested from all supported prior versions. | **Non-Destructive Expand/Contract Migrations + Container Image Swap.** Additive migrations run before code rollout; active calls continue on existing Asterisk bridges; canary instance validates health. Rollback swaps container image and runs down-scripts in under 30 minutes with zero data loss. | [06](06-deployment.md) §2; PRD T-12, AC-09.4 |

## 2. Architectural Decision Records (ADRs)

| ADR ID | Decision Title | Status | Core Impact & Trade-Off | Trace |
|---|---|---|---|---|
| **ADR-001** | Modular Monolith with Ports & Adapters | Accepted | Single Go deployable binary. Bounded contexts separated by package interfaces. Lower operational complexity than microservices; clean extraction path when load justifies it. | DECISIONS D-20, D-31 |
| **ADR-002** | Asterisk as Media Engine via Anti-Corruption Layer | Accepted | Asterisk 22.x LTS handles SIP/RTP/DTLS; 100% of call logic lives in Go Stasis application. Dialplan holds minimal entry points only. ACL absorbs channel churn. | DECISIONS D-15, D-16 |
| **ADR-003** | Participant Aggregate Identity (Not Channel) | Accepted | Call models N `CallParticipant` entities (never fixed caller/agent columns). Participant identity survives transfers and bridge migrations. Asterisk channel IDs are internal only. | DECISIONS D-17, D-18, D-32 |
| **ADR-004** | API-First Parity via ConnectRPC | Accepted | 100% of admin console and CLI operations execute through public ConnectRPC (HTTP/2 + JSON) endpoints. No private backdoor APIs exist. | BR-16, FBR-R1-11 |
| **ADR-005** | Optional Out-of-Band AI Media Pipeline | Accepted | AI consumes cloned audio via ARI snoop channels. AtsaPBX operates 100% without AI configured. AI failures never degrade call audio or drop calls. Partners bring own keys. | DECISIONS D-05, D-23, BR-14, BR-17 |
| **ADR-006** | Pure Function Compliance Engine | Accepted | DNC, calling hours, spend caps, and abandonment checks are pure, stateless functions. Zero I/O, zero database dependencies, 100% unit testable in milliseconds. | DECISIONS D-21 |
| **ADR-007** | IVR and Call-Flow as Data Engine | Accepted | Call flows are directed node graphs stored in PostgreSQL JSONB and executed by a pure fold function: `(State, Event) -> (NextState, Commands)`. Visual builder and API parity. | DECISIONS D-22 |
| **ADR-008** | Transactional Outbox Pattern | Accepted | Domain state and outbox events are committed in the same PostgreSQL transaction. Dedicated workers poll using `FOR UPDATE SKIP LOCKED` and publish to NATS JetStream. | [01](01-architecture.md) §3 |
| **ADR-009** | Multi-Tenant Row-Level Security (RLS) | Accepted | PostgreSQL sets `app.tenant_id` per session. RLS enforces tenant scoping on all queries. Missing tenant context fails closed automatically. | [01](01-architecture.md) §4, [05](05-security.md) §1 |
| **ADR-010** | Non-Destructive Expand/Contract Upgrades | Accepted | Database schema migrations are forward-compatible. Image swap and canary deployment allow zero-call-drop upgrades and 30-minute rollback guarantee. | [06](06-deployment.md) §2 |
| **ADR-011** | Semantic SIP Capacity Rejection | Accepted | Capacity exhaustion returns SIP `503 Service Unavailable` with `Retry-After: 30`, allowing carriers to reroute. Never send `486 Busy Here` for capacity limits. | DECISIONS D-11, BR-05 |
| **ADR-012** | Power Dialling Precedes Predictive Pacing | Accepted | Prove the outbound dialing loop with power dialing first. Layer predictive pacing mathematics on top in R2. | DECISIONS D-27 |
| **ADR-013** | Simultaneous Specialist Dispatch | Accepted | Specialist dispatch contacts qualified candidates simultaneously (first-accept-wins) to meet sub-15s connect target. Sequential calling rejected. | DECISIONS D-10 |
| **ADR-014** | Native `pgx/v5` Persistence with Parameterized SQL (No Heavy ORMs) | Accepted | Direct PostgreSQL 16 driver with connection lifecycle hooks for RLS (`SET LOCAL app.tenant_id`), binary stream ingestion (`pgx.CopyFrom`), and `FOR UPDATE SKIP LOCKED`. Heavy ORMs (GORM/Ent) rejected due to multi-tenant leak risk and high-throughput GC bottlenecks. | [TOOLSET.md](../TOOLSET.md) §2.2, DECISIONS D-34 |
| **ADR-015** | Permissive FOSS & Supply Chain Governance | Accepted | Platform strictly adopts latest stable permissive open-source libraries (MIT, Apache 2.0, BSD-3-Clause). Viral/copyleft licenses (GPL/AGPL), proprietary SDKs, and unreviewed AI agent packages prohibited. Automated `govulncheck` and Trivy gate CI builds. | [TOOLSET.md](../TOOLSET.md) §1, DECISIONS D-35 |
